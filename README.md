# Search_Tree

Одна задача — четыре способа её решить. В этом учебном проекте на C++20 я реализовал упорядоченное множество через отсортированный вектор, адаптер над `std::set`, прошитое AVL-дерево и B-дерево. Цель — разобраться в устройстве структур и сравнить скорость вставки и запросов на разных последовательностях данных.

Все контейнеры хранят **уникальные ключи** и имеют одинаковые основные методы: `insert`, `select`, `count_less`, `range_count`, `size` и `empty`. Повторная вставка не увеличивает размер. Тип ключа и компаратор задаются шаблонными параметрами; по умолчанию используется `std::less`.

## Что внутри

- `include/` — четыре контейнера и объявления парсера. У AVL есть балансировка, размеры поддеревьев и двусторонняя прошивка: ссылки на соседние ключи позволяют обходить дерево без стека. Узлами владеет дерево, его деструктор удаляет их итеративно. B-дерево хранит несколько ключей в узле, использует размеры поддеревьев для запросов и `unique_ptr` для владения.
- `src/input.cpp` — чтение команд и проверка аргументов.
- `apps/` — отдельная программа для каждого контейнера и общий исполнитель `command_runner.hpp`.
- `tests/unit/` — GoogleTest: методы контейнеров, повороты AVL, разбиения B-дерева, парсер и выполнение команд.
- `benchmarks/` — генерация последовательностей и замеры времени.
- `graphiviz/` — вспомогательный вывод деревьев в DOT для визуализации.

Одинаковый интерфейс не означает одинаковую стоимость операций: например, `select` у вектора обращается по индексу, а у адаптера `std::set` проходит по итераторам. Именно такие различия и исследует benchmark.

## Сборка

Команды ниже выполняются **из корня проекта в Ubuntu / WSL**. Нужны CMake 3.16+, компилятор с поддержкой C++20 и средство сборки. При первой настройке тестов CMake скачивает GoogleTest, поэтому нужен доступ к GitHub.

```bash
cmake -S . -B build/release -DCMAKE_BUILD_TYPE=Release \
  -DSEARCH_TREE_BUILD_APPS=ON \
  -DSEARCH_TREE_BUILD_BENCHMARKS=ON \
  -DBUILD_TESTING=ON

cmake --build build/release -j 2
```

Эта команда собирает приложения, тесты и benchmark. Любую из трёх групп можно отключить соответствующим флагом `OFF`.

Для сборки одной цели, например AVL:

```bash
cmake --build build/release --target search_avl
```

## Запуск приложений

Выбери нужную реализацию:

```bash
./build/release/search_vector
./build/release/search_set
./build/release/search_avl
./build/release/search_btree
```

Программа читает команды из стандартного ввода до EOF; при ручном вводе завершить его можно через Ctrl+D.

| Команда | Действие |
| --- | --- |
| `k x` | Вставить ключ `x` |
| `m i` | Получить i-й ключ по возрастанию, начиная с 1 |
| `n x` | Посчитать ключи строго меньше `x` |
| `q l r` | Посчитать ключи в **(l, r]**: левая граница исключена, правая включена |

Например:

```bash
echo 'k 8 k 2 k -1 m 1 m 2 n 3 q -1 8' | ./build/release/search_avl
```

Ответ:

```text
-1
2
2
2
```

Для файла с командами:

```bash
./build/release/search_avl < input.txt
```

Остальные приложения принимают тот же ввод. Ошибочная команда, недопустимый индекс или обратный диапазон завершают программу с сообщением в stderr.

## Тесты

Запустить все тесты:

```bash
ctest --test-dir build/release --output-on-failure
```

Только тесты AVL:

```bash
./build/release/search_tree_tests --gtest_filter='AVLTreeTest.*'
```

## Исследование производительности

```bash
./build/release/search_tree_bench
```

Введи размер `N`. Начать можно с 1000; большие размеры занимают заметно больше времени, поскольку часть запросов проходит по элементам линейно. Используй `1 <= N <= INT_MAX`: верхнюю границу текущий парсер ещё не проверяет.

Benchmark использует десять последовательностей: возрастающую, убывающую, случайную, одинаковые значения, повторы, чередование маленьких и больших, почти отсортированную, отрицательные числа с нулём, крайние значения `int` и один элемент. Для случайной перестановки задан seed 42.

Для каждого контейнера отдельно измеряются вставка, `select`, `count_less` и два варианта `range_count` — узкий и широкий. Запросы следуют порядку `data`, включая повторы; каждый блок содержит `data.size()` вызовов. Массив `ordered` хранит отсортированные уникальные ключи и нужен для подготовки рангов и границ.

Узкий диапазон задаётся соседними ключами, широкий охватывает половину уникальных ключей. При единственном ключе диапазон пустой; в сценарии `Single_element` выполняется по одному вызову.

Отдельно на возрастающих данных проверяются `First`, `Middle`, `Last` для `select` и `count_less`: по `N / 3` вызовов на случай с отдельным замером. Это ещё шесть измерений на контейнер.

Время измеряется через `std::chrono::steady_clock`; подготовка запросов и печать находятся вне замера. В выводе указаны число вставок, уникальных ключей и операций, общее время, среднее время на операцию и контрольные суммы запросов. Один запуск даёт один замер каждого сценария, а не статистику повторных прогонов.

Сохранить вывод в файл:

```bash
echo 1000 | ./build/release/search_tree_bench > build/release/N_1000.txt
```

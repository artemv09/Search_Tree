# Search_Tree

Учебный проект на C++20: четыре реализации упорядоченного множества — отсортированный вектор, адаптер над `std::set`, прошитое AVL-дерево и B-дерево. Я сравниваю, как они справляются со вставками и запросами: сначала по отдельности, затем при чередовании команд.

Все контейнеры хранят **уникальные ключи** и поддерживают пользовательский компаратор; по умолчанию используется `std::less`.

| Метод | Назначение |
|---|---|
| `insert(x)` | Добавить ключ; дубликат не увеличивает размер |
| `select(i)` | Получить i-й ключ в порядке компаратора, нумерация с 1; неверный индекс — `std::nullopt` |
| `count_less(x)` | Посчитать ключи, предшествующие x в порядке компаратора |
| `range_count(l, r)` | Посчитать ключи в интервале `(l, r]` |
| `size()`, `empty()` | Узнать размер и проверить пустоту |

## Как устроен проект

- `include/` — контейнеры и объявления парсера. Вектор использует бинарный поиск и доступ по индексу; `Set_Adapter` считает позиции проходом по итераторам. AVL хранит высоты, размеры поддеревьев и двустороннюю прошивку; B-дерево — несколько ключей в узле и размеры поддеревьев.
- `src/input.cpp`, `apps/` — чтение команд, общий исполнитель и четыре отдельных приложения.
- `tests/unit/` — GoogleTest: методы контейнеров, внутреннее устройство деревьев, парсер и выполнение команд.
- `benchmarks/` — раздельные замеры методов и смешанные нагрузки через Google Benchmark.
- `graphiviz/` — вывод деревьев в DOT для визуализации.
- [REPORT.md](REPORT.md) — отчёт об исследовании; `figures/` — его графики.

Узлами AVL владеет дерево; его деструктор освобождает их итеративно. B-дерево использует `unique_ptr`. Для обоих деревьев реализованы копирующие и перемещающие конструкторы и операторы присваивания: перемещение передаёт владение узлами без их копирования. Для обёрток над стандартными контейнерами достаточно автоматически генерируемых операций.

## Сборка

Команды выполняются **из корня проекта в Ubuntu / WSL**. Нужны CMake 3.16+, компилятор C++20 и средство сборки. При первой настройке тестов и смешанного benchmark CMake скачивает GoogleTest и Google Benchmark с GitHub.

Собрать все приложения, тесты и оба benchmark:

```bash
cmake -S . -B build/release -DCMAKE_BUILD_TYPE=Release \
  -DSEARCH_TREE_BUILD_APPS=ON \
  -DBUILD_TESTING=ON \
  -DSEARCH_TREE_BUILD_BENCHMARKS=ON \
  -DSEARCH_TREE_BUILD_MIXED_BENCHMARKS=ON

cmake --build build/release --parallel 2
```

Любую группу можно отключить её флагом `OFF`. Чтобы пересобрать только одну программу:

```bash
cmake --build build/release --target search_avl
cmake --build build/release --target benchmark_mixed
```

Для замеров используйте Release; одновременно другие тяжёлые задачи лучше не запускать.

## Приложения

Выберите одну реализацию:

```bash
./build/release/search_vector
./build/release/search_set
./build/release/search_avl
./build/release/search_btree
```

Все программы читают одинаковые команды из стандартного ввода до EOF (`Ctrl+D` при ручном вводе):

| Команда | Действие для числовых ключей |
|---|---|
| `k x` | Вставить x |
| `m i` | Вывести i-й ключ по возрастанию, начиная с 1 |
| `n x` | Вывести число ключей строго меньше x |
| `q l r` | Вывести число ключей в `(l, r]` |

```bash
echo 'k 8 k 2 k -1 m 1 m 2 n 3 q -1 8' | ./build/release/search_avl
```

Результат — `-1`, `2`, `2`, `2`, каждый ответ на отдельной строке. Вставки ничего не печатают. Диагностика ошибок выводится в stderr.

Чтение команд из файла:

```bash
./build/release/search_avl < input.txt
```

## benchmark_mixed: запуск и интерфейс

Это **консольная программа с параметрами командной строки**. Меню у неё нет: после запуска она не просит ввести N и не ждёт команды `k`, `m`, `n`, `q`. Нагрузку она создаёт сама, а настройки получает через аргументы после имени программы.

### 1. Собрать программу

Открой терминал Ubuntu / WSL и перейди в проект. Для текущего расположения проекта:

```bash
cd ~/CProjects/Search_Tree
```

Настрой отдельную Release-сборку только для смешанного benchmark:

```bash
cmake -S . -B build/mixed -DCMAKE_BUILD_TYPE=Release \
  -DSEARCH_TREE_BUILD_MIXED_BENCHMARKS=ON \
  -DSEARCH_TREE_BUILD_APPS=OFF \
  -DSEARCH_TREE_BUILD_BENCHMARKS=OFF \
  -DBUILD_TESTING=OFF \
  -DSEARCH_TREE_ENABLE_IWYU=OFF

cmake --build build/mixed --target benchmark_mixed --parallel 2
```

Исполняемый файл появится в `build/mixed/benchmark_mixed`. Если исходники изменились, перед следующим запуском повтори команду сборки.

### 2. Выполнить первый запуск

Проверить правильность небольшой серии без замеров времени:

```bash
./build/mixed/benchmark_mixed --mixed_suite=pilot --mixed_check_only
```

При успехе программа напечатает `Проверено конфигураций: 567`. Это проверка ответов контейнеров, а не результат измерения скорости.

Затем измерить небольшую серию и сохранить результаты:

```bash
./build/mixed/benchmark_mixed --mixed_suite=pilot \
  --benchmark_out=build/mixed/pilot.json \
  --benchmark_out_format=json
```

Больше ничего вводить не нужно. Дождись возврата приглашения терминала: результаты будут в консоли и в `build/mixed/pilot.json`. Вывод может появляться с задержкой; `Ctrl+C` прерывает запуск, после чего файл может оказаться неполным.

### Что именно программа измеряет

Каждый проход начинается с **пустого контейнера**. Далее вставки чередуются с одним видом запросов:

| Имя сценария | Какие команды выполняются |
|---|---|
| `Insert_Select` | Вставки и выбор элемента по индексу |
| `Insert_CountLess` | Вставки и подсчёт ключей меньше заданного |
| `Insert_RangeNarrow` | Вставки и подсчёт в узком диапазоне |
| `Insert_RangeWide` | Вставки и подсчёт в широком диапазоне |
| `InsertOnly` | Только вставки |

Измеряется **общее время всего смешанного блока**, а не отдельное время insert и запроса. Генерация команд, проверка ответов и уничтожение контейнера не входят в замер; выделение памяти внутри insert входит.

Ключи вставляются по возрастанию (`Increasing`), по убыванию (`Decreasing`) или случайно (`Random`). Запросы учитывают текущее состояние множества: select получает допустимый индекс, count_less — существующий ключ. Узкий диапазон содержит один ключ, широкий — половину текущего множества; при одном ключе диапазоны пустые.

Все классы получают одинаковую последовательность команд. Сравниваются `Sorted_Vector`, `Set_Adapter`, `AVL_Tree` и `B_Tree` со степенями `t = 2, 4, 8, 16, 32, 64`.

**Q — число команд, P — процент попыток вставки.** Например, Q = 10 000 и P = 50 означают 5000 вставок и 5000 запросов. Без дубликатов итоговый размер множества будет 5000.

### 3. Выбрать серию

Серия задаётся в форме `--mixed_suite=имя`:

| Имя | Число команд Q | Особенность |
|---|---|---|
| `pilot` | 1000 | Небольшая серия для первого запуска |
| `main` | 10 000 | Основная серия; используется без параметра `--mixed_suite` |
| `scale` | 1000, 10 000, 50 000 | Проверка влияния размера нагрузки |
| `seeds` | 10 000 | Три случайные последовательности: seed 42, 123, 2026 |
| `duplicates` | 10 000 | Каждый ключ вставляется дважды |
| `refine` | 10 000 | Доли вставок 30, 35, 40, 45% |

Во всех сериях, кроме `refine`, доли вставок — 10, 25, 50, 75, 90, 100%. При 100% запускается только `InsertOnly`. Во всех сериях, кроме `seeds`, seed равен 42.

Пример основной серии с сохранением JSON и полного вывода терминала:

```bash
./build/mixed/benchmark_mixed --mixed_suite=main \
  --benchmark_out=build/mixed/main.json \
  --benchmark_out_format=json \
  > build/mixed/main.log 2>&1
```

Здесь вывод перенаправлен в `main.log`, поэтому терминал будет молчать до завершения. Для другого запуска укажи другое имя файлов, чтобы сохранить предыдущие результаты.

### Параметры запуска

| Параметр | Что делает |
|---|---|
| `--mixed_suite=pilot` | Выбирает подготовленную серию |
| `--mixed_check_only` | Проверяет серию без замеров и завершает программу |
| `--benchmark_list_tests=true` | Показывает имена сценариев без выполнения |
| `--benchmark_filter='AVL_Tree'` | Выбирает сценарии по имени |
| `--benchmark_repetitions=7` | Задаёт число повторных измерений; по умолчанию 7 |
| `--benchmark_min_time=0.05s` | Задаёт минимальное время измеряемой работы для повтора; по умолчанию 0,05 с |
| `--benchmark_enable_random_interleaving=true` | Чередует повторения разных сценариев в случайном порядке; включено по умолчанию |
| `--benchmark_out=путь.json` | Сохраняет результаты в файл; родительский каталог должен существовать |
| `--benchmark_out_format=json` | Выбирает JSON для выходного файла |
| `--help` | Показывает справку Google Benchmark; наши два параметра описаны выше |

Семь повторений — не семь вызовов метода. Внутри каждого повторения Google Benchmark сам выбирает число проходов всей последовательности. Параметр `--benchmark_min_time` не ограничивает длительность программы: подготовка, проверки, остальные сценарии и повторения требуют дополнительного времени.

### Как читать результат

- `Time` в консоли и `real_time` в JSON — время **одного полного блока Q команд**; единицы указаны в `time_unit`.
- `Iterations` — сколько раз библиотека выполнила блок внутри отдельного повторения.
- `seconds_per_command` — среднее время одной команды смешанного блока в секундах; это не отдельная стоимость insert или select.
- `final_U` — итоговое число уникальных ключей; `insert_attempts` и `queries` — количество вставок и запросов.
- Строки `mean`, `median`, `stddev`, `cv` — среднее, медиана, стандартное отклонение и относительный разброс повторений. `cv` — не время.
- В JSON отдельные повторения имеют `run_type: "iteration"`, статистика — `run_type: "aggregate"`.

Для анализа сохраняй JSON со всеми повторениями и сравнивай медиану вместе с разбросом. Полные серии, особенно `scale` с линейными запросами Set_Adapter, могут работать долго.

## Раздельные измерения методов

`search_tree_bench` сначала заполняет контейнер, затем отдельно измеряет запросы. Размер N вводится через stdin:

```bash
echo 1000 | ./build/release/search_tree_bench > build/release/N_1000.txt
```

Используются десять паттернов: возрастающий, убывающий, случайный, одинаковые значения, повторы, чередование малого и большого, почти отсортированный, отрицательные числа с нулём, крайние значения int и один элемент. Дополнительно измеряются First/Middle/Last для `select` и `count_less`.

Это прежняя методика со `std::chrono::steady_clock`: один запуск даёт по одному замеру каждого сценария. Для исследования чередования вставок и запросов и оценки разброса используйте `benchmark_mixed`.

## Проверка заголовков через IWYU

Нужен установленный `include-what-you-use`. Для уже настроенной сборки:

```bash
cmake -S . -B build/release -DSEARCH_TREE_ENABLE_IWYU=ON
cmake --build build/release --clean-first --parallel 1
```

`--clean-first` заставляет повторно скомпилировать файлы и вызвать анализатор. Чтобы отключить проверку:

```bash
cmake -S . -B build/release -DSEARCH_TREE_ENABLE_IWYU=OFF
```
